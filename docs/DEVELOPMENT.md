# 开发说明

## 源码目录

| 路径 | 作用 |
| --- | --- |
| `public/` | 扩展入口、页面提取、导出窗口、后台和PDF预览 |
| `scripts/` | 构建、安装包打包及PDF检查 |
| `tests/` | 格式转换、数据提取、附件与浏览器集成测试 |
| `docs/` | 开发、验证、许可来源和图文素材 |
| `.github/workflows/` | 自动测试及通过后发布安装包 |
| `package.json`与锁文件 | 本地命令、版本号与可复现的依赖版本 |

## 从页面到文件

`content/index.js`维护页面入口，`dialog.js`负责轮次选择与导出；默认只读取正文，勾选思考后才补读思考与工具。弹窗使用Shadow DOM隔离宿主样式，主题读取网页背景，避免操作系统深色偏好覆盖网页当前主题。

数据提取由`extractor.js`协调。share优先交给`share.js`读取公开分享数据；chat按页面当前显示的分支滚动，逐条读取消息。`pageMetadata.js`只遍历单条挂载消息附近的React字段，复制允许导出的内容，不序列化整个组件或状态存储。

`historyBridge.js`在页面启动时观察已有的历史请求响应。它只接受同源`/api/v0/chat/history_messages`，只保存当前URL会话的消息字段，不读取请求体、Cookie、令牌或认证头。缓存限制为500条消息、约8MB字符串；缺失时回退到挂载数据与DOM。空的`MERGE`响应保留缓存，`REPLACE`响应先清空旧记录再写入；发起新回复、重新生成等请求时也清理旧缓存，避免将旧回答用于新导出。不会为了导出额外发送认证请求。

完整的消息快照保留`THINK`、`SEARCH`、`TOOL_SEARCH`、`TOOL_OPEN`等片段顺序；当页面只暴露分散的selector快照时，按generalFragment、parallelGroup和searchGroup还原思考与工具的交错顺序，并收集打开网页分组里的来源。再回退时按DOM位置组织已知记录，不把工具统一追加到最后；网页未提供的数据仍可能缺失。正文失去引用标记但保留来源数据时，在对应消息末尾列出来源，不猜测引用位置。`conversation.js`负责标题和原轮次，`markdown.js`负责层级、代码围栏及引用块。格式化层不猜测普通句子是不是代码，不调用外部模型改写原文。

滚动读取先比较首尾挂载的节点、消息标识与内容。确认全部消息已经挂载时直接结束，否则继续逐屏读取虚拟列表。每个阶段都有实际进度，结束或取消后恢复滚动位置。

`exportBundle.js`下载并缓存选中轮次的附件，把图片链接改为相对路径或PDF内嵌数据。相同URL复用一次读取结果，二进制文件避免重复压缩。附件窗口选1个时直接保存原始字节，选多个时复用打包流程，只产生一个ZIP下载；同名文件加序号，失败项进入清单。两种下载共用大小、图片类型和取消检查；失败不会伪装成空文件，真正的零字节文件则允许保存。长文件名保留扩展名。`background/index.js`负责允许来源检查、跨域附件读取、PDF临时存储。

2.2增加`formats.js`。同一份经过轮次筛选、附件本地化的数据交给四种格式，按实际勾选渲染，单格式无附件时返回文档，有多个格式或本地附件时统一生成ZIP。相对路径按段进行URL编码，归档文件名仍可读，修复空格、`#`和`%`被当作URL含义的问题。

HTML复用安全Markdown渲染器，原始HTML转义后再由DOMPurify清理；只嵌入本地`assets`图片或允许的光栅data URL，远程图片保留链接。输出无脚本，CSP限制自动加载，公式以MathML保存，不依赖外部字体。TXT遍历Markdown词元，保留代码字面内容、列表顺序、表格单元格和链接，不用全局删除标点的方式处理。JSON采用显式字段列表，未勾选思考时不输出`reasoning`，不直接序列化页面对象；公开格式见[JSON说明](JSON-FORMAT.md)。

格式名称存于`chrome.storage.local`，思考选项不持久化。新增格式与附件读取没有增加manifest权限。

share正文标题统一为“DeepSeek 对话记录”，chat保留可编辑标题；`conversation.js`根据会话URL区分，不依赖是否成功读取分享接口。导出时才为下载名称附加本地时间，避免把时间写进正文。PDF预览的`document.title`提供带时间的建议保存名，最终文件名仍由浏览器打印窗口决定。

`print/`是独立扩展页。Marked解析Markdown，DOMPurify清理HTML，KaTeX使用随包附带的字体，浏览器负责分页和保存PDF。2.2的HTML导出也使用本地KaTeX生成MathML，所以渲染库会进入内容脚本；打印页专用逻辑和字体仍留在独立扩展页。

## 构建与测试

Node.js24下执行`npm ci`、`npm test`、`npm run build`。构建使用esbuild，分别打包内容脚本、历史观察脚本、后台和打印页；只复制需要的资源，避免把整个源码目录再次放入安装包。

`npm run test:browser`使用Playwright的独立临时配置加载真实扩展，测试页面和网络响应使用可复现数据，并运行控件布局回归。首次运行先执行`npx playwright install chromium`，或设置`DSX_TEST_BROWSER`。单独检查布局可执行`npm run test:layout`，覆盖chat/share、深浅色、4种窗口宽度、36/40px原生按钮和Flex/Grid/剩余宽度容器，共96组；另检查缩放、刷新、侧边入口和输入框高度变化。

开发时修改代码后重新构建，在浏览器扩展管理页点击重新加载，再刷新DeepSeek。内容脚本和后台版本不一致时，旧页面可能继续使用旧代码，因此不能只刷新扩展而不刷新页面。

有本地分享捕获和对应附件时，可选运行：

```bash
node tests/replay.mjs path/to/share.json path/to/attachments
```

这些输入不随仓库分发。不要把登录信息、完整私人对话、签名下载地址或原始附件提交到Git。建议把新增复现缩减成`tests/fixtures`里的匿名数据，并注明它验证的边界。

## 发布版本

当前正式版本为2.2.0，v2.1.2作为历史稳定版本保留。发布工作流仅接受正式语义版本，不能把带`-rc`的包版本当作稳定版发布。商店审核与GitHub发布分别进行，准备流程见[上架材料](store/SUBMISSION.md)。

更新`package.json`、锁文件和`public/manifest.json`中的版本号，移除用于临时测试的`version_name`，并同步`CHANGELOG.md`、`docs/RELEASE-NOTES.md`。版本改动进入`main`后，Release工作流会运行单元测试、构建和浏览器测试，通过后创建对应的`v版本号`发行版，附上安装ZIP。也支持推送同名版本标签触发；标签必须与包版本一致，已有发行版的附件不会被覆盖。

GitHub自动提供的Source code是源码压缩包，不能直接当扩展加载。用户安装应选`DeepSeek-Export-Plus-版本号.zip`，自行开发再选择源码。

## 网页改版时怎么排查

先判断缺失发生在哪一层：分享返回数据、当前消息快照、DOM提取，还是文件格式化。普通搜索的类型是`SEARCH`，不能只判断`TOOL_`前缀；折叠思考为空时，需要先确定网页是否返回过内容。只有页面确实提供数据，提取器才能补齐。

调整数据结构后，用最小样例验证原问题，再运行单元测试和浏览器测试。涉及长对话时检查虚拟列表、重复消息、滚动位置恢复及切换会话；涉及下载时检查实际字节和失败提示，不能只看“下载请求已发送”。

## 产品与界面约定

面向需要长期保存DeepSeek网页对话的用户。支持chat和share页面，2.2增加HTML、TXT、JSON与多格式ZIP，保留Markdown和原有PDF打印预览。保持对话轮次、用户与DeepSeek身份、正文标题与代码结构；思考和工具记录使用引用，不额外加斜体。允许选取部分轮次。

导出在本机完成，无自建服务器、付费额度或遥测。只读取当前页面的对话及其附件。图片若来自网页预览接口，导出前明确说明是预览版。

扩展已有DeepSeek界面，背景跟随网页实际主题，不根据操作系统独自决定深浅色。弹窗内容在Shadow DOM中隔离宿主样式。正文、提示与选项共享高对比度前景色；说明通过字号和间距区分，不使用难读的浅灰。

小肥鱼作为图标和整理文件时的提示角色。保留蓝发、白色头饰等识别特征，避免夸张动画。导出窗口先显示标题与进度，完成后显示轮次、格式、附件选项。选择文字至少15px，键盘可操作，窄屏可滚动。加载状态只显示真实步骤，不伪造百分比。

默认不包含思考和工具；需要时由用户勾选。工具随对应思考段展示，不创建独立的工具章节。导出工具栏挂载在页面body中独立定位，按原生按钮实际矩形寻找底部控件行的空位并尽量居中，不修改输入框子元素或宿主样式。空间不足时移到输入框外侧，收为两个带可访问名称和悬停说明的图标；侧边也没有空位或没有输入区时放在对话内容顶部。ResizeObserver、滚动、输入及窗口事件合并到动画帧更新位置；定时检查负责路由切换和异步出现的输入框。

## 反馈与修改

提交问题时请说明浏览器及版本、插件版本、chat还是share页面、是否包含思考、预期结果与实际缺失位置。方便公开时可以附分享链接；涉及私人内容时，优先提供删去个人信息的最小样例。不要粘贴Cookie、令牌或带签名参数的下载地址。

修改代码后运行`npm test`和`npm run build`。涉及页面提取、文件下载或交互时，再运行`npm run test:browser`，并说明哪些部分使用了模拟数据、哪些经过真实页面验证。

请保留原项目及依赖的版权说明。引用其他项目实现时先核对许可证，不能因为“都是开源项目”就直接混用。
