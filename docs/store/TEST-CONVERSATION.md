# 审核对话与完整测试提示词

对应正式版2.3.0。Word、PNG及Word附件链接已由维护者实测确认正常；本表用于chat/share对照和商店审核复现。

## 附件怎么上传

商店资料包中`store/test-files`目录的文件均为虚构数据，没有私人信息、宏或联网脚本。解压后只上传各批目录里的文件，不要上传整个ZIP。

| 批次 | 文件 | 用途 |
| --- | --- | --- |
| 第一批，10个 | TXT、MD、HTML、JSON、CSV、PY、DOCX、PDF、PPTX、XLSX | 验证文件列表、中文文件名、原文件下载与不同文档的识别 |
| 第二批，4个 | PNG、JPG、WebP、GIF | 验证图片预览、特殊字符文件名、对话中嵌入图片及实际下载格式 |

所有数据都围绕纸飞机2个、纸船3个、纸风车5个，合计10个。文件带有`DSX-类型-序号`或结束标记，便于核对。XLSX的合计是SUM公式，PY只是本地求和示例，不需要执行。

DeepSeek允许上传的后缀可能随账号和网页版本变化。若某个文件被网页拒绝，记录后缀和提示，继续上传其余文件即可；不要改后缀冒充支持的格式。**网页未接收的文件不能用来判断插件是否漏下载。**如果第二批累计数量受限，可以拆成两轮，再按实际轮号检查。

## 第1轮：上传第一批文档

上传10个文件，等待解析完成，再复制以下内容：

```text
这是一个可以公开分享的浏览器对话导出测试，附件内容都是虚构数据。
请按文件名列出本轮你实际能读取的附件，分别说明内容和识别标记。不能读取的直接写“无法读取”，不要猜测内容。
请核对纸飞机、纸船和纸风车的数量，并给出合计。对于XLSX，区分单元格公式和计算结果；如果只能看到结果，也请说明。
最后写一个Markdown表格：文件名、实际读取情况、识别标记。以 ROUND-1-END 结束。
```

## 第2轮：上传第二批图片

```text
这是同一张虚构数量图的4种文件格式。请根据你实际能看到的图像，读出标题、三个项目的数量、合计和底部结束标记。
只比较你看得到的内容，不要推测原文件字节、压缩率或元数据是否相同。请用简短表格记录不同图片的可读情况，以 ROUND-2-END 结束。
```

## 第3轮：代码、正文层级和公式

下面这轮可以开启深度思考。插件只能导出网页实际提供的思考，不要求DeepSeek额外披露隐藏推理。

````text
请生成一篇“导出格式验收笔记”，用普通Markdown正文排版，不要把整篇包在一个代码块里。内容应包括：

1. 二级、三级标题；一个链接到正文标题的简短目录；粗体、斜体、普通引用、两级列表、任务列表。
2. 一个python代码块，写出count += delta以及根据count和delta设置start、end的分支。代码结束后另起一段写“AFTER-PYTHON：这句话是正文”。
3. 一个javascript代码块和一个text代码块。text中原样放入：count += delta; if count==1 and delta==+1 -> start=pos; if count==0 and delta==-1 -> end=pos.
4. 一个展示Markdown语法的代码块，里面包含三个反引号，外层使用四个反引号，避免围栏提前结束。
5. 一个3列表格，含中文、英文、带竖线的内容和行内代码。
6. 用LaTeX输出下列公式。行内公式使用单个美元符号，独立公式的前后各用单独一行的双美元符号，不要把公式放进代码块：
   a^2+b^2=c^2；二次方程求根公式；从0到1的x^2积分；求和Σ(k=1到n)k=n(n+1)/2；2×2矩阵；一个分段函数；一个带两行等号对齐的推导。保留根号、上下标、分式、希腊字母。
7. 提供一个正常的官方文档链接。代码中的<、>、&、反斜线和下划线应保持原样。

不要虚构你没有用过的工具或来源。以 ROUND-3-END 结束。
````

## 第4轮：搜索与打开来源

开启DeepSeek网页提供的搜索功能；若当前模式支持思考，也可同时开启。

```text
请搜索Python官方文档中sum函数的说明，实际打开一条官方结果，再查阅Python官方排序指南。根据你实际取得的页面，用几句话说明sum与sorted的不同作用，附上可点击的官方来源链接。
如果当前工具支持分次搜索或打开网页，请按需要正常使用；若工具不可用，直接说明，不要编造搜索、浏览记录。最后用一句话核对纸飞机2个、纸船3个、纸风车5个的合计，以 ROUND-4-END 结束。
```

这一轮用于对比“思考→搜索→继续思考→打开网页”等网页实际可见记录。工具是否存在由DeepSeek决定，提示词本身不能保证产生某种工具调用。

## 第5轮：长图与分页

```text
请写40段编号连续的中文测试正文，每段约70至90字，主题为整理个人学习笔记。每段以 START-01、START-02……START-40 开头，并以对应的 END-01……END-40 结束，不要省略中间段落。
第10、20、30段后分别插入一个短表格、一个python代码块和一个独立LaTeX分式。不要把整篇放进代码块。全文最后写 ROUND-5-END。
```

如果回复提前停止，继续生成到结束标记再测试。PNG会按阅读顺序分成多张，打包为一个ZIP；它导出的是重新排版的对话，不是带输入框和侧栏的网页截图。

## 第6轮：最终核对

```text
请简要总结这段测试对话：列出你实际接收的附件格式、数量合计、第三轮的代码语言与公式类型、第四轮实际使用的来源。不要重新输出全部长文。最后独立一行写 FINAL-CHECK-221。
```

## chat与share怎么对照

先在原chat测试，再创建分享链接。分享前检查内容适合公开；生成后用未登录窗口确认能否打开，记录是否要求登录。把有效share网址、测试日期、浏览器版本留给审核说明；不要用自动化截图里的`v221`或`format-demo`模拟地址。

建议按下面顺序检查，不需要每次导出所有格式。

| 检查 | 操作与预期 |
| --- | --- |
| 初次同意 | 扩展选项页点“暂不同意”，页面点击导出只进入说明，不读取对话；同意后刷新DeepSeek，再打开导出 |
| 默认范围 | 思考默认不选；先导出JSON，应该没有`reasoning`字段。普通正文来源链接仍可保留 |
| 六种格式 | 第3轮单独导出MD、HTML、TXT、JSON、Word、PNG；正文结束标记、代码之后的正文、表格与公式应完整 |
| Word | 完整解压ZIP，保留同级assets目录，打开DOCX并点击中文附件链接；尝试编辑正文、代码和表格。公式是图片，替代文本保存LaTeX，不是原生可编辑公式 |
| PNG | 第5轮单独导出，按文件名顺序看所有图片；START/END标记连续，没有空白尾图或缺字。超高图片或极复杂公式仍需目视确认 |
| 多格式ZIP | 第2至第4轮选择全部6种格式，勾选附件。一次下载，包含所选格式、assets和附件清单；文档附件不嵌入Word内部，仍保留同级文件及链接 |
| 思考和工具 | 勾选后导出第4轮MD、Word、PNG及PDF；对照网页工具与来源顺序。再取消勾选，确认思考不出现在新文件中 |
| 单个附件 | 从附件窗口只选PDF或PPTX，直接下载并打开，不能变成ZIP |
| 多个附件 | 从附件窗口选几种文档和图片，只下载一个ZIP。文档应与上传文件逐字节一致；图片按网页预览版核对，不要求与原图字节一致 |
| PDF | 点击底部PDF，再点“打印 / 保存为PDF”，用浏览器另存；保持现有流程，不加入多格式ZIP |
| 撤回 | 导出窗口和PDF预览保持打开，在扩展选项页撤回；窗口关闭、预览清空。再次导出需要重新同意，已下载文件仍保留 |
| 位置 | chat/share分别刷新、缩放并改变窗口宽度，入口不挡原生上传、发送和下降按钮 |

chat标题和share固定标题、来源网址、下载时间本来就会不同；先按原轮号和结束标记比较内容，不把这些差异当作丢失。分享页未公开的工具或附件不能凭空补回。若网页可见但导出缺少，请记录具体轮次、格式、思考选项和截图，并保留两份导出文件，便于定位。

通过以上测试后，再把新版本安装包、对应隐私说明和商店资料一起发布。新增同意页不等于两家商店已经审核通过。
